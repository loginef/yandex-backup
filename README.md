# Yandex Disk Backup

Резервное копирование файлов Яндекс Диска через REST API на Linux.
Требуются Python 3.9+, rclone и место для копии. Скрипт сохраняет список
файлов в SQLite, скачивает их потоками и проверяет размер и MD5.

## Установка и авторизация

Распакуйте файлы в отдельную папку и выполняйте команды из неё:

```bash
sudo apt update
sudo apt install python3 python3-venv rclone
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### Создание своего OAuth-приложения в Яндексе

Для этой настройки используйте **своё OAuth-приложение** с доступами к Диску
и его Client ID/Secret при авторизации в rclone.

1. Войдите в свой аккаунт Яндекса и откройте
   [создание OAuth-приложения](https://oauth.yandex.ru/client/new/id/).
   Нужна форма с настройкой платформ и Redirect URI: если предлагается
   выбор типа, выберите «Для авторизации пользователей».
2. Заполните название приложения и контактные данные.
3. В разделе «Платформы приложений» отметьте **«Веб-сервисы»** и добавьте
   Redirect URI **`http://127.0.0.1:53682/`**, включая завершающий `/`.
   Это локальный адрес обработчика авторизации rclone; адрес VPS сюда
   подставлять не нужно.
4. Добавьте следующие доступы к данным:

   | Доступ | Идентификатор |
   |---|---|
   | Доступ к папке приложения на Диске | `cloud_api:disk.app_folder` |
   | Чтение всего Диска | `cloud_api:disk.read` |
   | Доступ к информации о Диске | `cloud_api:disk.info` |
   | Доступ к Яндекс.Диску для приложений | `yadisk:disk` |

5. Создайте приложение и найдите его **Client ID** и **Client secret**.
   Введите их в rclone на следующем шаге; в Python-файлы их вставлять не нужно.

Не используйте для этого сценария упрощённую форму «Для доступа к API или
отладки»: согласно [документации Яндекса](https://yandex.ru/dev/id/doc/ru/register-api)
у неё фиксированный Redirect URI `https://oauth.yandex.ru/verification_code`,
а здесь нужен callback rclone, указанный выше.

### Настройка rclone

```bash
rclone config
```

Создайте remote с именем `yandex`, типом `yandex`. В поля `client_id` и
`client_secret` введите значения **своего приложения**, созданного выше;
**не оставляйте эти поля пустыми**. Затем авторизуйте свой аккаунт и
подтвердите запрошенные доступы.

На VPS без браузера выберите вариант без автоматического открытия браузера
и следуйте подсказкам rclone: [инструкция](https://rclone.org/remote_setup/).
При авторизации на компьютере с браузером должны использоваться Client ID
и Client secret того же собственного приложения.
Проверка подключения без вывода файлов или токенов:

```bash
rclone about yandex:
```

Запускайте скрипт под тем же пользователем, у которого настроен rclone.
Конфигурация должна быть доступна rclone без интерактивного запроса пароля.

## Запуск

Первый раз просканируйте Диск, затем запустите скачивание:

```bash
python backup.py scan --db ./state/manifest.sqlite
python backup.py status --db ./state/manifest.sqlite
python backup.py download --db ./state/manifest.sqlite --dest ./backup \
  --workers 4 --order asc \
  --connect-timeout 10 --read-timeout 15 --max-attempts 3
```

`asc` — от маленьких файлов к большим; `desc` — наоборот.
Размеры и пути берутся из manifest. Используйте один и тот же `--db` и
`--dest` при последующих запусках. Для продолжения достаточно повторить
`download`; сканирование заново не требуется.

- `verified` пропускаются. Остальные существующие файлы проверяются по
  размеру и MD5; несовпадающий готовый файл не перезаписывается.
- Частичные файлы имеют суффикс `.ydb-part`; докачка использует HTTP Range,
  если сервер его поддерживает. После докачки проверяется полный MD5.
- `--skip-failed` пропускает ранее неудачные файлы **только на этот запуск**.
  Без флага они снова попадают в очередь.
- Ctrl+C / SIGTERM прекращают выдачу новых задач и повторы. Уже начатый
  сетевой вызов может ждать тайм-аута; частичные файлы сохраняются.
- Тайм-аут чтения ограничивает ожидание данных при чтении, а не время
  загрузки всего файла. По умолчанию: подключение 15 с, чтение 30 с,
  4 потока и 3 попытки.
- `scan` добавляет и обновляет записи; отсутствующие на Диске старые строки
  не удаляются. Это не зеркалирование с удалением. Пустые папки и исходные
  локальные права/mtime не восстанавливаются.

Без `--db` и `--dest` используются `/mnt/storage/backup-state/manifest.sqlite`
и `/mnt/storage/yandex`. Параметры: `python backup.py download --help`.

## Как используется OAuth

При первом запуске скрипт сам читает токен из `rclone config show yandex`
и сохраняет его в `~/.config/yandex-backup/token.json` с правами `0600`.
Вывод команды не печатается. При истечении токена или ответе HTTP 401
обновление выполняет rclone (`about`) с временным приватным конфигом;
обновлённый токен сохраняется в кэш. Основной конфиг rclone код не меняет.
Скачивание файлов выполняет Python через REST API.

Для другого имени remote используйте `--remote ИМЯ` во всех сетевых командах.
Для другого аккаунта задайте отдельный кэш через `--token-file ПУТЬ`,
чтобы не использовать ранее сохранённый токен.

Если раньше использовалось стандартное приложение rclone или вы изменили
права своего приложения, настройте remote с собственными Client ID/Secret
и пройдите авторизацию заново. Скрипт продолжает использовать уже созданный
кэш, поэтому при переходе добавляйте
`--token-file ~/.config/yandex-backup/token-custom.json` в команды `scan` и
`download.py`. Этот новый путь нужно сохранять при следующих
запусках. Файлы резервной копии и manifest при этом менять не нужно.
